# 企业级知识库删除能力需求文档

## 1. 文档信息

| 字段 | 内容 |
| --- | --- |
| 文档名称 | 企业级知识库删除能力需求 |
| 版本 | v0.1 |
| 状态 | 待评审 |
| 编写日期 | 2026-07-30 |
| 适用系统 | Harness Agent 平台 |
| 适用模块 | 企业知识库、知识文档管理、检索审计、Artifact 知识回写 |

## 2. 背景

当前 Harness Agent 平台已经具备企业级知识库目录、文档入库、文档列表、文档详情、知识检索、Agent Knowledge Profile 和 Artifact 回写能力。随着用户开始上传需求文档、测试策略、Runbook、日志样本和 Agent 产物，平台需要提供可控的删除能力，用于处理误上传、过期文档、测试数据清理和知识治理。

知识库删除属于企业级数据治理能力，不能简单物理删除。平台应优先采用“软删除 / 归档”策略，保证删除行为可审计、可追踪、可扩展到后续恢复能力。

## 3. 改造目标

1. 用户可以在知识库 UI 中删除当前目录下的知识文档。
2. 删除应采用软删除方式，将文档状态标记为 `deleted`，默认不再出现在文档列表和检索结果中。
3. 删除操作应记录审计事件，包括操作者、traceId、文档 ID、目录和来源信息。
4. 删除文档时，其知识切片应同步从默认检索范围中排除。
5. 删除操作应具备二次确认，避免误删。
6. 当前阶段不支持删除默认知识目录，只支持删除知识文档。

## 4. 用户角色

| 角色 | 删除诉求 |
| --- | --- |
| 平台管理员 | 清理错误或过期知识文档 |
| 测试工程师 | 删除误上传的需求、策略、用例和测试数据 |
| 运维工程师 | 删除过期 Runbook、日志样本或故障材料 |
| 审计人员 | 查看删除行为、删除原因和关联影响 |

## 5. 删除范围

### 5.1 本期支持

1. 删除知识文档。
2. 删除后文档不出现在默认文档列表中。
3. 删除后文档切片不参与默认知识检索。
4. 删除后保留文档元数据、来源 URI、内容摘要、删除人和删除时间。

### 5.2 本期不支持

1. 删除默认知识目录。
2. 批量删除。
3. 删除恢复。
4. 物理清除数据库记录。
5. 删除对象存储中的 Artifact 原始文件。
6. 删除检索审计记录。

## 6. 功能需求

### 6.1 文档删除入口

知识库页面右侧文档详情面板应提供“删除文档”按钮。

按钮展示规则：

1. 未选择文档时不展示删除按钮。
2. 搜索命中结果对应真实文档时可以删除。
3. 删除按钮应使用危险操作样式，例如红色边框或红色文字。
4. 点击删除按钮后必须弹出二次确认。

### 6.2 删除确认

确认内容应包含：

1. 文档标题。
2. 所属知识目录。
3. 来源 URI。
4. 删除影响说明：删除后默认列表和检索结果将不再展示该文档。

用户确认后，前端调用后端删除接口。

### 6.3 后端删除接口

后端应提供文档删除接口：

```http
DELETE /api/v1/knowledge/documents/{document_id}
```

接口行为：

1. 校验用户具备 `knowledge:write` 权限。
2. 校验文档属于当前租户。
3. 将文档状态更新为 `deleted`。
4. 记录 `deleted_by` 和 `deleted_at`。
5. 返回删除结果。

响应示例：

```json
{
  "deleted": true,
  "document_id": "doc_001"
}
```

如果文档不存在，应返回：

```json
{
  "deleted": false,
  "document_id": "doc_001"
}
```

### 6.4 列表过滤

默认文档列表接口应排除已删除文档。

```http
GET /api/v1/knowledge/documents?collection=requirements
```

后续可扩展 `include_deleted=true` 给管理员查看删除记录，本期不强制实现。

### 6.5 检索过滤

知识检索应排除已删除文档及其切片。

```http
POST /api/v1/knowledge/search
```

检索结果中不应出现 `status=deleted` 的文档。

### 6.6 审计要求

删除操作应记录审计事件：

| 字段 | 内容 |
| --- | --- |
| event_type | knowledge.document.deleted |
| resource_type | knowledge_document |
| resource_id | document_id |
| metadata.collection_name | 所属知识目录 |
| metadata.source_uri | 来源 URI |
| metadata.title | 文档标题 |

## 7. 数据模型需求

`knowledge_documents` 表应增加或具备以下字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| status | text | 文档状态，默认 `active` |
| deleted_by | text | 删除操作者 |
| deleted_at | timestamp | 删除时间 |

默认状态：

| 状态 | 说明 |
| --- | --- |
| active | 正常可见、可检索 |
| deleted | 已删除，默认不可见、不可检索 |

## 8. UI 验收标准

1. 用户选择某个文档后，右侧详情面板展示“删除文档”按钮。
2. 点击删除按钮后出现二次确认。
3. 用户确认删除后，文档从中间列表消失。
4. 删除成功后显示成功提示。
5. 删除后再次搜索原内容，不再命中该文档。
6. 删除失败时显示错误信息。

## 9. 后端验收标准

1. 删除接口返回正确结果。
2. 删除不存在文档不抛 500。
3. 删除后文档列表不再返回该文档。
4. 删除后知识检索不再返回该文档切片。
5. 删除操作写入审计事件。
6. 后端测试通过。

## 10. 后续增强

1. 管理员查看已删除文档。
2. 文档恢复。
3. 批量删除。
4. 删除原因必填。
5. 删除审批流。
6. 定期物理清理和归档策略。
7. 与外部知识源同步删除状态。
